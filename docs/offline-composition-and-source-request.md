# Four-component composition and minimal source request

The earlier 220-test candidate did **not** compose preparation-ahead with the subprocess worker flow. It separately tested the preparation Pool, and its child fixture synthesized metadata instead of consuming prepared metadata/cover. Checkpoints, manifest transactions and worker completion were connected; preparation was not. This follow-up closes that specific local gap, without introducing a launcher, provider downloader or scheduling service.

`composed_upload.run_prepared` takes a prepared artifact only after the existing worker boundary owns the upload token and validates the fenced claim/global hold. Context binds job, claim generation, recipe and destination. The fixture child validates the descriptor against its explicit fixture destination/recipe and the claim; this does not qualify a real transport or wrapper. Its exact audio bytes go into the worker's checked snapshot; exact metadata bytes and optional cover enter the retained attempt directory. The locally authored child consumes those bytes, puts audio/art through receipt-validated checkpoints, runs register/catalog/analysis, emits the fresh report, and returns to bounded decoder/fenced completion. Empty cover remains absent. Analysis completion is required only when the prepared metadata actually contains audioAnalysis and registration is a duplicate.

On successful local completion, consumer/worker payload references are dropped and the active Pool lease is released **before the upload token is handed to another consumer**. A deterministic two-consumer regression verifies this ordering. On uncertainty or decode failure, the Pool closes, drops its next reservation and retains its active lease while the durable global/job holds remain. No retry, release-on-timeout, automatic reclamation or checkpoint-reset policy is added. One shared Pool is still required across all workers: independent per-worker pools do not meet the global two-artifact limit. The composed attempt's retained disk allowance is 35 MiB (32 MiB audio + 2 MiB cover + metadata/report allowance); the worker-only default remains 33 MiB. This does not alter the Pool's existing two-artifact payload ceiling or claim a two-copy process RSS bound across parent/child/disk.

The deterministic composition fixture blocks the first track's synthetic PUT callback inside the child while the parent prepares exactly one next local track. It asserts active=1,next=1 and rejects another reservation, then completes both serially. It verifies exact retained audio/metadata, cover receipts and empty-cover omission, analysis completion hold, fresh reports and final fenced statuses. There are no provider calls or HTTP requests. Other tests exercise stale recipe/context, wrong source hash, ambiguous subprocess timeout preventing next consumption, duplicate registration with no analysis, malformed metadata, descriptor tampering, payload lifetime, and two-consumer lease/token handoff. This is genuine **local component composition**, not real worker integration or live throughput evidence. Real-handler registration/CAS validation remains a separate test layer.

Until a real shared preparation owner is identified, preparation-ahead remains a proposed seam, not an installable flag.
