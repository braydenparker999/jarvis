# Curated playlists and durable import

Implementation is based on the live playback release `ed9ab565d4c4147f3a2a5582474ad6915f15c798`; the literal main branch was behind that release when inspected. The supplied eight-playlist artifact is now integrated byte-for-byte as `public/drawercast/curated-playlists.json`. Its raw length is 968,384 bytes and SHA-256 is `86bc49aac0a6c1b1fab06e6020e956b5e40d21cd252acde97f9ee7a7d61e9bcf`. Transport integrity was verified before parsing; no contents were reconstructed or invented.

The existing `PlaylistFiles` importer is retained. Exact IDs now take precedence over colliding paths, fallback uses unique exact paths with source constraints, and malformed/oversized files are rejected before mutation. Basename/title guessing is removed. Imported track order and intentional duplicate occurrences remain intact; importing creates new playlists rather than silently merging same-name user playlists. Counts distinguish matched, unavailable and ambiguous references.

Playlist writes are serialized and resolve on IndexedDB transaction completion. Import additions and the optional one-time receipt are atomic. Failed commits do not publish partial UI state. Concurrent edits/deletions remain in memory and subsequent queued saves include the imported additions. A persisted-state mismatch fails closed instead of overwriting another tab's changes.

The seed hook runs asynchronously after native R2 mapping restoration or catalog completion, not after an arbitrary nonempty library. It waits until all curated references resolve to available mapped R2 tracks. Exact same-name existing playlists are preserved without modification. A durable one-time receipt prevents repeated insertion and resurrection after deletion. No recurring timer, automatic audio playback or credential change is added.

The artifact contains 3,810 distinct R2 references, with playlist counts 145, 1,139, 984, 448, 288, 472, 270 and 64. A read-only comparison with the current 6,828-track native catalog matched every reference by exact ID: zero missing, zero ambiguous, zero fallback matches. Catalog verification details are recorded in `artifact-validation.json`. Publication remains with the existing release owner; no deployment is performed from this branch.

Checks: 258 focused tests passed; three Chromium integration checks passed, including real file selection, durable storage, forced transaction abort, the actual eight-playlist artifact, delayed-fetch UI responsiveness, and offline-preview storage isolation. That browser check fails against the frozen live source at the reproduced exact-ID-versus-path collision. Evidence is under `docs/evidence/poweramp-playlists-20261012/`. Playback transport is unchanged apart from the asynchronous catalog-ready seed hooks. The preview storage adapter is updated for the new durable playlist method; preview writes remain session-only and never open IndexedDB.
