# Private current work

The existing private Relay **Requests** entry opens **Current work**, using the same conversation colors, type, separators and request inspector. Projects expand into owner-entered goals and separately saved tasks. Each task shows its owner, truthful state, latest meaningful authenticated execution update, blocker, record time and an **Evidence and result** action. Expanding a task keeps its latest saved or corrected result beside that execution update; the inspector retains the original reply, all correction versions, completion attestation and history.

Project and goal are optional labels supplied by the owner when creating a work request. They are stored atomically in the existing immutable specification event; no new table, schema column, authorization, subscription or schedule is introduced. A goal requires a project. Exact request retries must retain the labels as well as UUID, body, title and scope; conflicting labels return409. A guarded retry resolves the same verified root request's labels using the existing immutable retry relationship. Historical records remain unassigned. Ordinary unclassified chat history stays in the conversation and is not invented into a current task; a genuinely acknowledged execution or explicit guarded retry can still appear.

**Queued** requires a saved work request without an execution acknowledgement. **Working** requires the existing authenticated execution claim with its current lease. Waiting, failed, expired, cancellation-pending and completion-unverified work stays **Blocked**, with its specific reason. **Finished** means either explicitly attested work completion bound to the owning grant/run, original reply and result version, or an acknowledged cancellation clearly labeled as such. A callback receipt, reply wording, project label or public Muse marker cannot establish execution or completion. A later text correction cannot rewrite the accepted reply or the original completion version.

Presentation fields are returned only on existing authenticated private device REST routes. The existing strict cached private MCP output schemas and response shape remain unchanged. Public shared entries, public readers and public publications receive no project labels, owner results or private progress. Clients validate private provenance and exact request association before rendering updates; all titles, labels, progress and blockers remain inert text. Results use the existing sanitized rich-text renderer.

The list reuses the existing fenced job-change cursor, bounded pagination, partial-read recovery, stale-state labeling and visible-only refresh cadence. There is no AI summary generation, additional timer or per-task detail read. Project, goal and task expansion uses records already in the private controller. Only the explicit evidence action requests one exact detail. Rendering starts with50 current and50 finished tasks, with local Show more controls; these controls do not fetch another history or execute work. The initial bootstrap and reload still require the original complete bounded change-feed recovery.

The added closed fixtures cover exact retry/conflict, lost accepted response with an edited goal, more than one change page, progress on an old request, heartbeat exclusion, lease expiry, completion/correction association, malformed labels and forged public provenance, strict old MCP compatibility, privacy and ordinary historical chat exclusion. Existing assertions and qualification gates remain intact. The mobile fixture covers360×800,390×844 and390×520, expansion request counts, evidence reads, refresh/reload and the public/private boundary. Fixtures use fictional records and blocked live egress.
