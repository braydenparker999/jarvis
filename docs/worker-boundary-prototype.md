# Offline worker integration boundary

This extends the isolated checkpoint/manifest prototype into a locally authored parent/child flow. It does not patch or invoke Mast's actual worker, uploader, watchdog, schedules or credentials. Supplied snippets are reference data only. The original public client and Poweramp UI remain unchanged. No real network requests, media uploads or measured speed gains.

`run_attempt(manifest, claim, token, stop_paths, command, decode, audio_bytes, ...)` is the proposed parent seam. `command(report_path, attempt_id, claim, audio_path)` returns argv for a trusted local child. Child must use `guarded_request` for each actual attempt and `write_report` after validated registration/analysis. There is no monkey-patching, discovery or invocation of actual Mast processes. The test fixture is the only child wired to this protocol.

Order: validate immutable audio → pre-token stop check → token → post-token stop check → fenced durable job/global hold → unique audio snapshot → subprocess → fresh report validation → exact-snapshot local decode → fenced manifest completion. Uploader and decoder execute in new POSIX process groups. The guard kills the cooperating group on timeout/output/accounting failure and waits for the leader; a leader exiting with surviving group members is rejected and the group killed. This does not establish remote terminality; global hold persists on any failure. Interrupted parents also leave the committed hold. All cooperating starters must honor that same shared manifest hold. Successful duplicate analysis keeps its checkpoint `analysis_acknowledged_completion_pending` journal as retained evidence even when the outer manifest records local completion; the job is no longer eligible and no checkpoint reset API is introduced.

The manifest lock held across each request prevents cooperating ownership changes during that request, at the cost of blocking other manifest operations until it returns. The network callback must be synchronous: no detached requests, background descendants or retries; every descendant must obey the same request guard. It must not reacquire the manifest lock. Lock order is global token → checkpoint journal → manifest; all real participants must be checked for inverse ordering. File-based stop creation can race after a check; checks cannot cancel a request already dispatched, and no such guarantee is claimed. A durable hold, not a catalog read, prevents new uploads after uncertainty.

File/path and child-process trust assumptions remain explicit: local durable flock/rename/fsync semantics, canonical paths, cooperating writers, no malicious child/administrator bypass. Unique attempt directories and report nonces prevent accidental stale reuse; they do not authenticate malicious subprocess output. Diagnostic output is drained/discarded with a 64 KiB default total limit, and is never classified into automatic retry. The decoder seam now takes a nonblocking argv factory and uses the same bounded subprocess guard; this prototype does not run real FFmpeg. A launcher sets inherited RLIMIT_FSIZE before exec, avoiding preexec_fn in multithreaded callers. Post-child/post-decode snapshot checks use nonblocking, no-symlink regular-file opens and read at most expected size plus one byte. Claim/attempt fields are prototype schema, not claimed current production fields. This boundary intentionally sacrifices liveness on uncertain outcomes.

Validation uses locally authored subprocesses, synthetic bytes and fake in-memory server responses only. Coverage includes a full child PUT/register/catalog/analysis/report/decode path; reports missing, stale, false or followed by process death; partial-output timeout; parent process death after durable hold; decode false/exception; changed snapshot; late stale completion; durable stop arriving while token wait is blocked; stop between PUT and register; auth failure; and global hold preventing another job after ambiguity. Existing real-handler tests separately verify registration proofs and analysis CAS using fake storage.
