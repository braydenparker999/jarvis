Privacy policy

This policy covers the personal YouTube Archive application operated by Brayden Parker and these information pages.

Information the application accesses

The application processes public YouTube video URLs, IDs, creator IDs, titles, publication dates, and downloaded video and audio. Manual requests may include a destination, maximum quality, and request label.

With the owner's consent, the app uses the Google Drive API to inspect the configured destination and its children, create folders, upload files, and verify file IDs, sizes, checksums, and archive tags. It requests the https://www.googleapis.com/auth/drive scope, which technically permits broad Drive access. The application is designed to work within the configured archive destination; it does not scan the owner's unrelated documents or request Gmail or Contacts access.

How information is used

Data is used to discover requested videos, save them to Drive, detect duplicates, verify successful uploads, recover from failures, and diagnose operation. The application does not sell Google user data, use it for advertising, or use it to train generalized AI or machine-learning models.

YouTube Archive's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Storage, access, and sharing

  • Google Drive: the finished videos and destination folders remain in the owner's account. Files inherit destination sharing settings. Anyone with access to a shared destination may be able to view or download them; the archiver does not make shared destinations private.
  • GitHub: disposable Actions runners process the files. The public archive repository records video and creator metadata, request labels where supplied, status, Drive file IDs, sizes, checksums, and completion times. Public workflow logs and summaries can also reveal archive activity. A Drive file ID does not itself override Drive permissions.
  • Credentials: the OAuth client secret, refresh token, and destination configuration are kept in repository secrets. Access tokens and upload sessions are used during a run. The app is designed not to print credentials or commit them to source or archive state. Authorized repository administrators and workflow code can use configured secrets.
  • Other providers: Google/YouTube, GitHub, Microsoft Azure hosting, and Cloudflare network egress process requests needed to provide their services. The configured YouTube proxy handles YouTube traffic; Drive uploads do not use that proxy by default. These services may retain their own operational logs under their policies.

The operator and anyone granted repository or Drive access may inspect the data available to them. No Google credentials or Google account data are collected through these static information pages.

Retention and deletion

Archived files remain in Drive until the owner deletes them. Temporary runner media is deleted after successful upload and checkpoint, and cleaned up when the job ends. Run-summary artifacts are configured to expire after 14 days; Actions log retention follows repository settings.

Archive metadata remains in Git history unless deliberately removed. Deleting a current record does not erase older commits, public copies, or provider logs and may allow a video to be downloaded again. The owner can disable workflows, delete Drive files, remove repository secrets, and remove records or the repository as appropriate.

Control and revocation

The owner can stop future processing by disabling the GitHub workflow and can revoke Google access at Google Account connections. Revocation stops future authorized Drive operations; it does not delete files already uploaded or metadata already recorded. Deleting the refresh-token secret also prevents subsequent unattended authentication.

Information pages and contact

These pages use no analytics scripts, tracking pixels, forms, or application cookies. Hosting providers may log normal web requests.

For support or privacy questions, contact the operator through the project issue tracker. Issues are public: never include credentials, private links, or personal account data. Policy updates will appear here with a revised effective date.
